# 本地阅读伴侣设计

## 产品目标

构建一个本地运行、面向桌面端的个人阅读伴侣。用户在手机微信读书中阅读，在电脑网页中决定下一本读什么、快速记录实时思考、恢复阅读上下文，并通过每日回顾和阅读节点复盘减少“读完即忘”。

第一版以书籍为中心。文章、论文和视频只作为外部资料链接关联到书籍或想法，不抓取和管理全文。

## 产品原则

- 捕捉优先：记录原始想法不超过一个输入动作，AI 整理不能阻塞保存。
- 本地优先：业务数据只保存在本机 SQLite，不做账号、云同步或远端部署。
- 微信读书只读：同步书架、进度、划线和个人想法，不假设能够反写微信读书。
- 轻量结构：只保留能直接帮助选择、继续阅读和复盘的数据。
- 可解释推荐：队列和推荐展示理由，不使用不可理解的综合分数。
- 原始内容不丢失：AI 生成内容与用户原始文字分开保存，用户随时可以修改或忽略建议。

## 核心使用流程

1. 用户手动点击“同步微信读书”，将书架、笔记概览和相关书籍详情写入本地数据库。
2. 用户从书库中选择一本主线书、若干支线书，并把其他书加入主线候选、支线候选或快速阅读池。
3. 阅读过程中，用户在电脑端通过快捷入口输入自由文本。系统先本地保存，再异步分类和关联。
4. 首页每天展示 1～3 条旧想法，用户可以补充、确认、标记观点变化或跳过。
5. 手动同步后若主线书进度明显推进，系统提示阶段复盘；读完时提示读后复盘。
6. 主线书完成后，系统展示主线候选第一名及其“为什么想读”，由用户确认是否开始。

## 页面结构

### 今日阅读

- 当前主线书、微信读书进度和继续阅读链接
- 支线书列表
- 自由文本快速记录框
- 最近想法和未解决问题
- 每日回顾 1～3 条
- 手动同步按钮和上次同步时间

### 阅读队列

- 主线候选、支线候选、快速阅读池
- 拖拽调整队列内部顺序
- 编辑想读原因
- 完成主线后的队首推荐

### 书库

- 展示微信读书同步的真实封面
- 搜索和轻量筛选
- 设置阅读状态和加入队列
- 展示 AI 生成、用户可编辑的阅读体感

### 单本书工作室

- 读前：阅读理由、希望解决的问题
- 读中：微信读书划线、微信读书想法、本地想法
- 读后：阶段复盘、最终复盘和遗留问题
- 外部资料链接

### 回顾

- 每日旧想法回顾
- 补充、仍然认同、观点变化、跳过
- 阶段复盘历史

### 设置

- 微信读书和 AI 配置状态
- 数据库路径和数据边界说明
- 最近同步结果

## 阅读角色与队列

系统同时允许一本主线书和多本支线书。主线与支线是当前阅读角色，不是书籍永久属性。

候选书分为三个独立、有序的队列：

- 主线候选：较长、较严肃或需要连续投入的书。
- 支线候选：可碎片阅读、中断后容易恢复的书。
- 快速阅读池：预计几小时内完成、适合通勤或调节状态的书。

用户通过拖拽调整顺序。系统不会自动替换当前主线，只在完成后提出可解释的队首建议。

## 阅读体感

AI 根据书名、作者、简介、分类和字数生成四项轻量信息：

- 预计阅读时间
- 阅读强度：轻松、适中、深度
- 连续性：适合碎片读、一般、建议连续读
- 最多两个风格标签

所有字段标注为 AI 估计，允许用户覆盖。缺少 AI 配置或调用失败时，其余功能正常工作。

## 记录与回顾

快速记录默认关联当前主线书。原始文字先写入数据库，AI 分类和关联在后台进行。初版不要求用户在输入前选择类型。

每日回顾采用简单规则，从尚未沉淀、已有一段时间未查看且近期未跳过的想法中选择 1～3 条。阶段复盘在同步后的明显进度变化或读完时提示，也允许手动触发。所有提示均可忽略。

## 外部资料

外部资料只保存标题、URL、类型和关系说明，可以关联到书籍或某条想法。第一版不下载、不解析全文，也不建立完整的跨载体知识图谱。

## UI 方向

采用“编辑部式阅读桌面 + 知识档案卡”：

- 当前主线书使用真实封面、轻微透视和书脊厚度，形成适度实体感。
- 队列和书库保持规整、易比较、易拖拽，不使用重型 3D 书架。
- 预计时长、强度和连续性以克制的小标签表达，不堆叠维度。
- 整体使用温暖纸张色、深绿色和少量金色点缀，配合衬线标题与清晰正文。
- 封面墙和基础统计作为阅读档案，而不是首页核心。

## 技术架构

- Next.js + TypeScript 单体应用
- SQLite + Drizzle ORM
- Tailwind CSS 和少量轻量动画
- 单用户、localhost 运行，无认证系统
- 微信读书与 OpenAI-compatible API 仅由服务端调用
- API Key 通过本地环境配置提供，不写入数据库或 Git
- 数据库存放在本地数据目录并加入 `.gitignore`

## 同步策略

第一版只在用户点击按钮时同步：

- 首次同步完整书架和笔记概览。
- 只主动拉取当前主线、支线和最近阅读书籍的详细进度与笔记。
- 其他书籍在打开详情时按需拉取。
- 每次同步记录开始时间、结束时间、成功部分和错误信息。
- 部分失败时保留旧数据，绝不清空本地想法、队列和复盘。

## 核心实体

- `Book`：书籍元数据与微信读书标识
- `ReadingState`：主线、支线、候选、搁置、读完等状态
- `QueueItem`：队列类型、排序位置和想读原因
- `Thought`：原始文字、关联书籍、处理状态和 AI 建议
- `Highlight`：微信读书划线
- `Reflection`：阶段与读后复盘
- `ResourceLink`：外部资料链接及关系说明
- `BookProfile`：轻量阅读体感
- `SyncRun`：同步执行记录

微信读书导入字段与本地字段分离。同步按外部唯一标识 upsert，只更新导入字段。

## 错误与隐私边界

- 日志不打印任何 API Key。
- 页面只显示连接状态，不回显完整 Key。
- 同步失败继续展示上一次成功数据。
- AI 失败不回滚已经保存的想法。
- 封面加载失败时显示包含书名的纸质占位封面。
- 不自动访问用户保存的外部链接。
- 不提供远端部署配置和公共分享入口。

## 验收标准

- 用户可以在约 5 秒内保存一条关联当前书的想法。
- AI 失败不会导致原始记录丢失。
- 队列拖拽排序在重启服务后保持不变。
- 系统只允许一本当前主线书，同时允许多本支线书。
- 重复同步不会覆盖本地想法、队列和复盘。
- 同步部分失败时仍可继续使用旧数据。
- 读完主线后能展示队首候选及其想读原因。
- 每日回顾和阶段复盘可以完成、跳过且不会形成强制流程。
- 关键页面包含空状态、加载状态和错误状态。

## 第一版明确不做

- 手机端、PWA、云同步和多人协作
- 微信读书数据反写
- 完整书籍正文和正文问答
- 外部文章、论文、视频全文解析
- 复杂知识图谱、自由画布和间隔重复算法
- 重型 3D 阅读时钟、复杂分享图和社交功能
