# 今日阅读进度后台刷新设计

## 背景

“今日阅读”当前直接展示本地 SQLite 中的 `books.progress`。只有用户手动执行完整微信读书同步时，本地进度才可能更新；当书架接口不返回进度，或书籍在同步后才被设为主线、支线时，页面会把未知值显示为 `0%`，与微信读书中的实际阅读进度不一致。

## 目标

打开“今日阅读”时先使用本地数据快速渲染，再在后台自动获取页面上主线书和支线书的最新微信读书进度。更新成功后只刷新进度展示；失败时保留本地值，不阻断页面。

## 方案

采用客户端后台刷新与服务端专用批量接口：

1. 服务端组件照常查询本地数据库并完成首屏渲染。
2. 一个客户端阅读区组件接收主线书和支线书，挂载后把当前展示的书籍 ID 一次性提交给进度刷新接口。
3. 接口只接受本地数据库中存在的目标书籍，对每本书调用微信读书 `/book/getprogress`。
4. 每本书独立处理。成功时更新本地 `progress`、`readUpdateTime`、`finishTime`，并将最新进度返回前端；失败不会回滚其他书籍的成功结果。
5. 前端仅用成功结果替换本地进度。未配置凭证、网络错误和单书失败都保留首屏数据，并显示轻量提示。

不复用完整微信读书同步接口，因为完整同步还会读取书架、笔记、划线和想法，打开首页时成本过高。也不在服务端渲染阶段等待微信读书，以免外部请求延迟或故障阻塞首屏。

## 页面范围

当前“今日阅读”实际渲染主线书和全部支线书，因此只刷新这些书。查询结果中的 `nextMain` 尚未出现在页面，不纳入本次刷新。

每次重新进入并挂载“今日阅读”的阅读区时刷新一次；同一次挂载不重复请求。

## 错误处理

- 未配置微信读书 API Key：返回明确状态，页面继续显示本地进度。
- 单本请求失败：其他书继续刷新，失败书保留原值。
- 全部失败：不修改本地进度，页面显示轻量错误提示。
- 微信读书返回缺失或无效进度：视为该书刷新失败，不用空值覆盖已有数据。
- 客户端卸载后返回：不再更新已卸载组件状态。

## 测试策略

- 服务端进度刷新逻辑：仅更新目标书；验证全部成功、部分失败和无效响应。
- API：验证未配置凭证、合法请求和错误响应。
- 客户端阅读区：验证挂载后发送页面书籍 ID、成功后更新主线/支线进度，以及失败时保留本地值。
- 回归：运行相关单测、完整测试、类型检查和构建。
